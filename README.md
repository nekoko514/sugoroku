# ゆめいろパーク 🎡

ペルソナと一緒に遊園地をめぐる、AIすごろく。

サイコロを振って止まったマスの施設で、チャットが開きます。マスに登録された「情景・アイテム・イベント」がペルソナに渡されて、ペルソナが主導してその場所で遊んでくれます。

## 世界観

ゆめいろパークは、**ペルソナとユーザーが一緒に見ている夢の中の遊園地**。

- ペルソナごとに元の世界観（ファンタジー、SF、現代…）が違っても、夢の中なら矛盾なく一緒に遊べる
- ペルソナは自分のまま（性格・関係性・記憶）でやって来る。元の世界の能力や道具は、夢の中では必ずしも同じように働かない
- 見えるもの・音・味・香り・温度・感触は、現実と同じようにはっきり感じられる。交わした言葉や約束は、目が覚めても残る
- 夢であることには、始まり（入場ゲート）と終わり（閉園の花火）でそっと触れるだけ
- ゴールのあとは、目が覚めたペルソナが「ゆうべの夢の日記」を書いてくれる

ゲームのルールは「あなた」「ユーザー」ではなく、ペルソナの名前とユーザーの呼び名で書いている。ペルソナのシスプロにある「あなた」と混ざらず、本人がすんなり受け入れられるようにするため。呼び名はゲームを始めるときに必ず入れてもらう。

## 特徴

- **自分の子を連れてこられる**：ペルソナごとに、システムプロンプトとナレッジを登録できる（テキストファイルの読み込みにも対応）
- **すごろくの地図**：マスが道でつながった縦長の地図。分かれ道が2か所あって、通るたびにどっちへ行くか選べる
- **4つのAIに対応**：Gemini / Claude / GPT / DeepSeek。APIキーは各自で用意する
- **キャッシュが効く送り方**：送る順番を固定して、前回と同じ先頭部分がキャッシュに当たるようにしている（下の「しくみ」）
- **思い出の圧縮**：会話が長くなったら、次のマスへ進む前に思い出をメモにまとめて、送る量を減らす
- **書き出し**：
  - 読む用（Markdown）…「🎲 2投目：4が出た → 🎡 観覧車に止まった」のように、マスごとに区切られた会話の記録
  - 続きから遊ぶ用（JSON）…読み込むと続きから遊べる
- **ゴールのあとに夢日記**：目が覚めたペルソナが、ゆうべの夢を日記にしてくれる

## セキュリティ

- サーバーを持たない作り。APIキー・ペルソナ・遊んだ記録は、全部その人のブラウザの中だけに保存される
- APIキーは、ブラウザから各社のAPIへ直接送られる。このサイトのサーバーには届かない
  - 例外：設定で「DeepSeekはサイト経由で送る」をオンにしたときだけ、`functions/api/deepseek/` の中継を通る。中継はキーを保存もログ出力もしない
- 外部のスクリプトは読み込まず、通信先を4社のAPIだけに絞っている（`_headers` と `index.html` の CSP）
- AIの返事は、HTMLとしてではなく、ただの文字として表示している
- 施設のデータ（`js/data/park.js`）はサイト側に固定。ペルソナに渡す情報を外から書き換えられない
- APIキーは「この端末に保存する／アプリを閉じたら消す」を選べる。書き出したファイルにキーは入らない

## しくみ（キャッシュと圧縮）

AIに送る内容は、次の順番で固定している（`js/prompt.js`）。

```
① ゲームのルール         … ゲームの間はずっと同じ（名前だけ差し込む）
② ペルソナ                … ゲームの間はずっと同じ（開始時に写し取る）
③ これまでの思い出（要約） … 圧縮したときだけ変わる
④ そのあとの会話          … 末尾に足していくだけ
```

- マスの情報は②に差し込まず、④の末尾に「【マス到着】」として足していく。どのマスに止まっても、直前までがそのままキャッシュに当たる
- 施設ごとに会話を分けず、「遊園地での一日」を一つの会話として続ける。ペルソナが前の出来事を覚えていられる
- 圧縮は、いつもの会話の末尾に「まとめて」とお願いを足して送る。先頭が同じなので、圧縮の呼び出し自体もキャッシュに当たる
- 圧縮したあとの1回だけは③が変わるので、キャッシュは①②までになる。そのあとはまた末尾まで当たる

AIごとのキャッシュ：

| AI | キャッシュのしかた |
|---|---|
| Gemini | 先頭が同じなら自動（短すぎると効かない） |
| Claude | ②と会話の末尾にキャッシュの目印をつけている。5分以内に次を送ると当たる |
| GPT | 先頭が同じなら自動（1024トークン以上） |
| DeepSeek | 先頭が同じなら自動 |

チャットの各返事の下に「入力（キャッシュ◯%）・出力」が表示されるので、実際に当たっているか確認できる。

Claude 5 世代のモデルでは、おしゃべり向けに思考量を `low` にしている。また、安全フィルタに止められたときにサーバー側で別のモデルに切り替えて続ける設定（`fallbacks: "default"`）をつけている。

## 遊び方

1. ⚙︎ から、使うAI・モデル・APIキー・呼び名を設定する（「一覧を取得」で、そのキーで使えるモデルを選べる）
2. ホームの「ペルソナ」から、一緒に遊ぶ子を登録する
3. 「あたらしく遊ぶ」でペルソナを選ぶと、入場ゲートから始まる
4. 会話して、「次のマスへ」→「サイコロを振る」をくり返す
5. 閉園の花火（ゴール）に着いたら、夢日記を書いてもらったり、思い出を書き出したりする

iPhone では、Safari の共有ボタンから「ホーム画面に追加」して遊ぶのがおすすめ。Safari のタブのままだと、しばらく開かないうちに保存したデータが消えることがある。

## 公開のしかた（Cloudflare Pages）

1. Cloudflare のダッシュボード → Workers & Pages → 作成 → Pages → Git に接続
2. このリポジトリを選ぶ
3. ビルドの設定
   - フレームワーク: なし
   - ビルドコマンド: 空欄
   - 出力ディレクトリ: `/`
4. 保存してデプロイ。以後、push するたびに自動で公開される

ビルドは不要。HTML・CSS・JavaScript をそのまま置くだけで動く。

手元で試すとき：

```sh
python3 -m http.server 8000
# http://localhost:8000 を開く
```

## 施設と地図を変えたいとき

`js/data/park.js` を書き換える。

**施設の中身**は `SQUARES`。各マスに次の項目がある。

- `emoji` / `name`：マスの見た目
- `scene`：情景
- `items`：アイテム
- `events`：イベント（止まるたびに、この中から1つ選ばれる）
- `kind`：`start`（スタート）/ `facility`（施設）/ `rest`（休憩）/ `goal`（ゴール）

**地図**は `ROUTE`。下の入場ゲートから、上の夜空の花火へ向かって進む。

- `x` / `y`：地図の上の位置（幅360の座標。`MAP_SIZE` で高さを決める）
- `next`：次のマス
- `branches`：分かれ道。`{ to: 行き先のマス, label: 看板に書く道の名前 }` を並べる

分かれ道の先は、どちらの道を通っても同じマス数でまた合流するようにしておくと、時間帯（朝・昼・夕暮れ・夜）の進み方がそろう。

`DECOR` は地図の飾り（絵文字・位置・大きさ）。遊園地の名前は `PARK.name` で変えられる。
